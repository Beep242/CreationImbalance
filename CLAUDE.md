# CLAUDE.md

## What this is

A toy computational-cosmology **hypothesis test** in Python: could a dark sector existing in a pre-Big-Bang state survive a transition into our universe and bias the matter/antimatter asymmetry? It integrates a 5-variable comoving ODE reaction network across 12 scripted experiments plus parameter sweeps, 2D heatmaps and a Monte Carlo fine-tuning scan, then regenerates `docs/results.md` from whatever the runs actually produce. Everything is in dimensionless "model units" — not GeV/seconds.

## Layout

- `main.py` — entry point: calls `run_all_experiments()`, then writes `docs/results.md`.
- `src/cosmology/` — `constants.py` (model units, `DEFAULT_G_STAR`, `DEFAULT_RANDOM_SEED`), `expansion.py` (`SimplifiedExpansion` is what every config builds; `FriedmannExpansion` is an interface-compatible alternative that nothing in the pipeline ever selects — `tests/test_expansion.py` only).
- `src/dark_sector/` + `src/transition/` — `PreBigBangState` → `run_transition()` → `HotEarlyUniverseState`.
- `src/reactions/` — every rate law (`annihilation.py`, `dark_interactions.py`); `src/visible_sector/particles.py` owns the eta definition.
- `src/baryogenesis/` — `sakharov.py` (the three condition switches), `asymmetry.py` (`classify_outcome`).
- `src/simulation/` — `ode_system.py` (RHS), `runner.py` (solve_ivp driver), `model_a.py` / `model_b.py` (config builders), `run_experiments.py` (498-line orchestrator of all 12 experiments — the real control flow lives here), `config_loader.py`.
- `src/analysis/` + `src/visualization/` — conservation checks, Model A/B comparison, fine-tuning scan, auto-generated conclusions; plots and heatmaps.
- `configs/` YAML parameter sets, `docs/` prose + generated results, `results/` generated CSV/PNG (git-tracked), `tests/` 49 pytest tests.

## Commands

```
pip install -r requirements.txt
python main.py        # full suite; rewrites results/ and docs/results.md
pytest tests/ -q      # 49 tests
```

Run both from the repo root: `main.py` does `sys.path.insert(0, ".")`, `tests/conftest.py` inserts the repo root, and all output paths (`results/data`, `results/plots`, …) are relative. No lint config, no CI, no Makefile, no `pyproject.toml`/`setup.py` — so no Python version is pinned anywhere (developed on CPython 3.10). `requirements.txt` is the whole dependency story: numpy, scipy, matplotlib, pandas, pyyaml, pytest.

## Architecture notes

- State vector is **comoving**: `y = [a, N_matter, N_antimatter, N_dark, E_rad]` with `N = n*a^3` and `E_rad = rho*a^4`, so Hubble dilution never appears in the RHS — only genuine reactions change these. Column names in `ode_system.Y_LABELS`.
- Every rate term is computed once in `ode_system._reaction_terms()`; both `rhs()` and `reaction_diagnostics()` call it, which is what lets `src/analysis/conservation_checks.py` test bookkeeping bugs rather than solver drift. Don't duplicate rate math elsewhere.
- Sakharov conditions are applied *upstream* of the ODE, in `sakharov.build_effective_dark_interaction_params()`: CP off symmetrizes the two couplings to their geometric mean (R_eff = 1); B-violation off sets a gate flag on `DarkInteractionParams`; `thermal_equilibrium` sets `equilibrium_factor = 1` (washout).
- `build_model_a()` and `build_model_b()` both return a `SimulationConfig` fed to `run_simulation()`. They differ only in initial conditions and parameters, never in the ODE itself — that is the point of the A/B comparison.
- Dark↔visible channels ramp in via `transition.reaction_activation_factor(t, tau) = 1 - exp(-t/tau)`.
- Solver: `solve_ivp` method `Radau`, `rtol=1e-8`, `atol=1e-10`, with an automatic LSODA retry when the first solve reports failure.

## Conventions & gotchas

- **The transition must never inject an asymmetry.** `run_transition()` always seeds `N_matter0 == N_antimatter0`; any nonzero eta must emerge from the reaction network. This is the project's core scientific commitment (see `src/transition/transition.py` docstring) — an edit that breaks it invalidates every result in the repo.
- Docstrings tag claims as **ESTABLISHED PHYSICS** / **SPECULATIVE ASSUMPTION** / **NUMERICAL APPROXIMATION**. Preserve that three-way discipline in new code and docs.
- `docs/results.md` and everything under `results/` are generated by `main.py` — never hand-edit. Both are git-tracked, so running `main.py` dirties the working tree.
- `run_transition()` raises `ValueError` for any `DarkSectorMode` other than `PARTICLE_POPULATION` (the discrete B-violating channel needs a particle population). `FIELD_BACKGROUND` / `GENERIC_ENERGY_DENSITY` exist only as the standalone dilution helpers `field_background_density` / `generic_energy_density` in `src/dark_sector/dark_sector.py` — exercised by `tests/test_dark_sector_modes.py`, with the raise itself covered in `tests/test_transition.py`. Neither mode is wired into the reaction network.
- `coupling_to_visible` (elastic heating) is a deliberately *open*, non-conservative energy injection, excluded from the closed-system energy check. It defaults to 0 and **nothing in `run_experiments.py` ever sets it nonzero** — the comment in `ode_system._reaction_terms()` about "dedicated coupling-to-visible sweeps" describes sweeps that do not exist in this repo.
- `configs/*.yaml` keys map 1:1 onto `build_model_a`/`build_model_b` kwargs, but their only loader is `src/simulation/config_loader.py`, which **nothing in the repo imports** — `run_experiments.py` builds every config inline. The YAMLs and that loader are for interactive use only (see `configs/README.md`); editing them changes nothing about `python main.py`.
- `SimplifiedExpansion` is kinematic: `H(a)` is imposed and does not respond to energy injected or removed by reactions. `g_star` is a constant 10.
- Plot modules call `matplotlib.use("Agg")` at import — no display required.
- eta here is `(N_m - N_a)/(N_m + N_a)`, **not** the baryon-to-photon ratio; `OBSERVED_BARYON_TO_PHOTON_RATIO` is a reference constant that no code path reads (a docstring mentions it), never a fit target.
- No environment variables, no secrets, no network calls anywhere in the code.
